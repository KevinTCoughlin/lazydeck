# Changelog

All notable changes to lazydeck are documented in this file.

This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Entries after v0.2.0 are generated by
[release-please](https://github.com/googleapis/release-please) from
[Conventional Commit](https://www.conventionalcommits.org/) PR titles: `feat:`
lands under **Added**, `fix:` under **Fixed**, and so on. Changes merged since
the last release are collected in the open `chore(main): release …` pull
request rather than an Unreleased section here. Earlier entries follow
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.2.0](https://github.com/kevintcoughlin/lazydeck/compare/v0.1.0...v0.2.0) (2026-10-05)

### Added
- `lazydeck serve`: a local HTTP + SSE API (connection-file handshake under
  `$XDG_RUNTIME_DIR/lazydeck/serve.json`) exposing discover, pair, deploy,
  logs, and job polling to editor integrations, with a `--fixture` backend
  for hardware-free testing and a systemd user unit
  (`lazydeck-serve.service`).
- Engine integrations built on `lazydeck serve`:
  - Godot addon: export, deploy, logs, and cancel from the editor.
  - Unity package: build, deploy, logs, and cancel from the LazyDeck window,
    plus a batch-mode CLI (`Editor/Cli/LazyDeckCli.cs`) with `BuildAndDeploy`
    and `SyncLogs` entry points for `-batchmode -quit -executeMethod` in CI.
  - Unreal Engine editor plugin (Slate dock) with a "Cook and Package" action
    that drives UAT `BuildCookRun` for Linux/Win64 before Deploy. Authored
    without a UE toolchain; see `integrations/unreal/README.md` for
    validation status.
  - Optional argv/launch-command support in all three deploy clients.
- Chat webhook notifications (Discord, Slack, or generic JSON) when a
  `lazydeck serve` deploy or log-sync job finishes, via a `webhooks` setting
  in `devices.toml`.
- TUI: mouse support, fuzzy filter, periodic auto-refresh, a responsive
  multi-panel layout, confirmation before delete, and the exact underlying
  command shown in the log.
- User-customizable `config.yml` for keybindings and custom commands.
- `install.sh`: checksum-verified, smoke-tested, atomic install of a release
  archive into `~/.local` (or a custom prefix); `VERSION=nightly` installs
  the rolling nightly build of `main`.
- `lazydeck version --check` reports whether a newer stable release exists
  (opt-in; lazydeck never checks for updates on its own).
- Release channels and distribution: a nightly prerelease rebuilt from
  `main`, `vX.Y.Z-rc.N` release candidates as GitHub prereleases, a
  multi-arch `ghcr.io/kevintcoughlin/lazydeck` container image, automatic
  Homebrew tap updates, and a Sigstore (cosign keyless) signature on
  `checksums.txt`.
- `lazydeck version` / `--version` command reporting build metadata (version,
  commit, build date, builder, platform), injected via `-ldflags` at release
  time and falling back to Go build info for `go install`.
- Persistent, dedicated trust-on-first-use SSH host-key handling for devkits
  (a separate `known_hosts` file), replacing the silent accept-any policy.
  Opt into strict rejection of changed keys with `LAZYDECK_SSH_STRICT=1`.
- Debian packages (`.deb`) for linux/amd64 and linux/arm64 that bundle the
  binary, Python runtime, and checksum-verified pinned uv, built via
  GoReleaser/nFPM.
- Software Bill of Materials (SBOM) and reproducible third-party license
  notices (`NOTICE`, `THIRD_PARTY_GO.md`) shipped in release archives.
- Reproducible development/test container (`Containerfile` + `.dockerignore`).
- `lazydeck mcp` Model Context Protocol server exposing lazydeck operations
  to MCP-compatible clients.
- Deploy `argv` wiring through API, CLI, and MCP layers for passing custom
  arguments to deploy operations.
- Supply-chain baseline: pinned tool versions (`mise.toml`), Dependabot,
  CodeQL, `SECURITY.md`, issue/PR templates, and this changelog.

### Changed
- The config directory is now `$XDG_CONFIG_HOME/lazydeck` (default
  `~/.config/lazydeck`) on every OS, matching the documentation. Config found
  at the previous OS-native location (e.g. `~/Library/Application Support`
  on macOS) is migrated once, without overwriting an existing file.
- Config writes (`internal/config`) are now atomic (same-directory temp file +
  file/directory fsync + rename) and only mutate in-memory state after a
  successful write.
- The Go client no longer clamps caller-supplied operation deadlines to a
  fixed 60s timeout; the per-operation context controls the deadline.
- Cancelling an operation now tears down the whole `uv`→python→ssh/rsync
  process group (Unix), not just the direct child.
- The TUI serializes device operations: a device that is busy rejects new
  manual operations, and stale completions can no longer clear a newer one.
- Vendored `devkit_client`: game names are shell-quoted before entering remote
  commands; discovery snapshots are taken under a lock; `sync-logs` honors the
  requested folder and login.
- Releases are automated with release-please from Conventional Commit PR
  titles, and every release is installed from its published assets and
  signature/provenance-verified on Linux and macOS after it ships.
- CI runs Go tests (race/vet) on Linux and macOS, real Python unit tests and
  Ruff, and a GoReleaser config check + snapshot; all GitHub Actions are
  pinned to immutable commit SHAs with least-privilege permissions.
- Attribution for the vendored LGPL-2.1 `python-zeroconf` is now complete,
  including its full license text.
- Installed runtime discovery now covers archive, user-data, Homebrew-style,
  and Debian layouts and provisions the locked Python environment in a
  writable per-user cache.

### Fixed
- Deployment filters, shortcut payloads, and delete argument mapping for the
  current SteamOS devkit protocol.
- Unreal cook/package rejects quotes and line breaks in the project and
  output paths spliced into the `BuildCookRun` command line.
- `sync-logs` passed an attribute the vendored API ignored and dropped the
  login override, so logs never synced; both are corrected.
